# ابزار مدیریت WireGuard روی MikroTik

اسکریپت Python برای ساخت شبکه WireGuard، تولید فایل کاربران و ادامه اجرای نیمه‌کاره با حفظ کلیدها و IPها.

نگهدارنده: [whoisGray](https://github.com/whoisGray) · [راهنمای کامل انگلیسی](README.md)

## پیش‌نیاز

- macOS یا Linux و Python 3.9 یا بالاتر؛ ویندوز به‌صورت بومی پشتیبانی نمی‌شود.
- ابزار `wg` از بسته `wireguard-tools`؛ هیچ پکیج pip لازم نیست.
- RouterOS پایدار 7.12.1 یا بالاتر از شاخه 7، دسترسی API و حساب دارای مجوزهای لازم.
- برای دستگاه کاربران، برنامه WireGuard.

روی مک دارای Homebrew:

```bash
brew install python wireguard-tools
python3 wg_manager.py --help
```

## شروع

فقط برای استقرار جدید، فایل نمونه را کپی و ویرایش کن. فایل کاربران فعلی را جایگزین نکن:

```bash
cp -n users.example.csv users.csv
```

هدر باید `id,name,name_fa` باشد. شناسه و نام انگلیسی هر کاربر باید یکتا باشند. ستون `name_fa` یک برچسب نمایشی Unicode است و می‌تواند به هر زبانی باشد.

هیچ IP سرور پیش‌فرضی وجود ندارد. مقادیر نمونه زیر را جایگزین کن:

```bash
python3 wg_manager.py --plain-api \
  --host YOUR_MANAGEMENT_IP \
  --endpoint YOUR_PUBLIC_IPV4 \
  --user YOUR_API_USERNAME \
  --wan YOUR_WAN_INTERFACE \
  --csv users.csv --workdir wg-output -v
```

رمز به‌صورت تعاملی دریافت می‌شود. API معمولی روی پورت پیش‌فرض 8728 رمزگذاری ندارد؛ از شبکه مورداعتماد یا VPN موجود استفاده کن. سرویس `api` و فایروال باید دسترسی IP مدیریت را مجاز کنند.

برای API-SSL گزینه `--plain-api` را حذف و `--tls-fingerprint YOUR_VERIFIED_SHA256` را اضافه کن. پورت پیش‌فرض این حالت 8729 است. اثرانگشت گواهی را از مسیر مدیریت مورداعتماد بگیر. پورت سفارشی با `--api-port` قابل تنظیم است.

این دستور روتر را فقط بررسی می‌کند؛ فایل‌های محلی شامل state خصوصی و برنامه تغییرات ایجاد می‌شوند. پس از بررسی `wg-output/plan.json` و تهیه و دانلود بکاپ روتر، همان دستور را با `--apply --backup-confirmed` اجرا کن.

## نمایش جزئیات اجرا

با `-v` یا `--verbose` درخواست‌های API، پارامترهای غیرحساس، تعداد ردیف‌های پاسخ و مراحل اجرا در stderr نمایش داده می‌شوند. این خروجی دستور قابل کپی در ترمینال روتر نیست؛ نمایش مسیر و پارامترهای API است.

رمز، اطلاعات ورود، کلید خصوصی و پارامترهای ناشناخته پنهان می‌شوند؛ محتوای پاسخ‌ها چاپ نمی‌شود. لاگ همچنان ممکن است شامل IP، نام کاربران و اطلاعات توپولوژی باشد؛ قبل از اشتراک‌گذاری بررسی‌اش کن.

## اجرای مجدد و افزودن کاربر

همیشه همان پوشه `wg-output` و پارامترهای اتصال و شبکه را حفظ کن. اجرای مجدد برای کاربران قبلی Peer تکراری نمی‌سازد و کلیدها و IPها را تغییر نمی‌دهد.

برای کاربر جدید یک ردیف یکتا به انتهای `users.csv` اضافه کن و check/apply را تکرار کن. شناسه یا نام کاربر قبلی را تغییر نده. حذف ردیف از CSV دسترسی را لغو نمی‌کند؛ غیرفعال یا حذف‌کردن Peer روی روتر، اجرای بعدی را متوقف می‌کند تا دسترسی لغوشده خودکار بازنگردد.

روی RouterOS قبل از 7.15 شناسایی Peer از طریق comment انجام می‌شود؛ استقرار جدید روی نسخه‌های بالاتر از `name` هم استفاده می‌کند.

## فایل‌ها و بازیابی

- `wg-output/state.json`: کلیدها، IPها و مالکیت استقرار؛ خصوصی نگه دار و بکاپ رمزگذاری‌شده بگیر.
- `wg-output/clients/*.conf`: فایل اتصال هر کاربر پس از apply موفق؛ فقط فایل همان شخص را به او بده.
- `wg-output/manifest.csv`: فهرست فایل‌ها و IP کاربران.
- `wg-output/plan.json`: برنامه تغییرات.
- `wg-output/preflight-snapshot.json`: وضعیت روتر پیش از apply.
- `wg-output/rollback.rsc`: حذف دستی و بازبینی‌شده اشیای همین استقرار؛ خودکار اجرا نمی‌شود.

پس از خطا state یا اشیای نیمه‌کاره را حذف نکن. علت را بررسی و همان دستور را تکرار کن. اینترفیس جدید هنگام ساخت غیرفعال است؛ اعتبار اجرایی آدرس و قوانین وابسته پس از فعال‌سازی دوباره بررسی می‌شود. اگر بررسی نهایی شکست بخورد، برنامه تلاش می‌کند همین اینترفیس تازه فعال‌شده را دوباره غیرفعال کند. rollback کامل یا تراکنش اتمیک وجود ندارد.

## محدوده پشتیبانی

پیش‌فرض‌ها: اینترفیس `wg-staff`، آدرس `10.220.10.1/24` و UDP 51820. رنج و پورت را پیش از اولین استقرار تغییر بده. فایروال بالادستی باید پورت UDP انتخاب‌شده را مجاز کند.

IP عمومی باید مستقیم روی WAN باشد و دقیقاً یک مسیر پیش‌فرض فعال در main از همان WAN خارج شود. تداخل IP، قوانین فعال raw/mangle/routing، dstnat، VRF اضافی، policy فعال IPsec غیر-template و ECMP نیازمند بررسی اختصاصی‌اند. برای عبور از بررسی، تنظیمات موجود را پاک نکن.

VPN برای اینترنت IPv4 است؛ دسترسی به روتر، شبکه‌های خصوصی، کاربران دیگر و عبور IPv6 مسدود می‌شود. این ابزار kill switch دستگاه نیست. handshake، اینترنت، DNS/IPv6 و سلامت تونل‌های قبلی را پس از نصب آزمایش کن.

## توسعه و Git

```bash
python3 -m unittest -v
python3 wg_manager.py --version
```

تست‌ها آفلاین‌اند و از کاربران نمونه استفاده می‌کنند؛ موفقیت آن‌ها تضمین سازگاری با تمام روترها نیست.

فایل کاربران واقعی، state، کانفیگ‌ها، بکاپ‌ها و آرشیو خروجی نباید وارد Git شوند. `.gitignore` تاریخچه قبلی را پاک نمی‌کند؛ اگر این اطلاعات قبلاً کامیت شده‌اند، پیش از انتشار عمومی تاریخچه را جداگانه بررسی کن.
